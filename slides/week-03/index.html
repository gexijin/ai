Coding agents

The main part of today. What a coding agent is, the tools around it (VS Code, Git, GitHub), and how to use one safely.

An agent is an LLM with tools, in a loop

Plan: read files, make a plan

Act: edit files, run commands

Check: test, read errors

Repeat until done

Session 1: LLMs can use tools. Session 2: RTutor runs the LLM in a loop for you. A coding agent puts the two together. It reads your files and makes a plan, then acts: edits files and runs commands such as git or a PubMed search. Then it checks: runs the code, reads the errors, and tries again. It keeps looping until the job is done, so one request can turn into dozens of steps. You stay in the loop by approving commands and checking the result.

VS Code is a free app from Microsoft for editing files in a folder. Think of it as a workbench. Explorer on the left shows the files in the folder you opened; the agent can only work in that folder, so always use File → Open Folder. The chat panel on the right is where GitHub Copilot lives (Activity 1); the terminal at the bottom is where we run Claude Code (Activity 2). Source Control shows what the agent changed and lets you save or undo. You don't need to read code: you read the result in a browser and the change list in Source Control.

Git: save points for your folder

Commit

A save point you can go back to

Push

Send your commits to GitHub

GitHub Pages

Turn a repository into a website

Commit before and after the agent works.

Git is free version control: it keeps save points of your folder, called commits. GitHub is a website that keeps a copy of your folder, called a repository; push sends your new commits there. GitHub Pages turns a public repository into a free website (Activity 1). Why this matters for agents: an agent can change many files at once. If you commit before and after each step, you can always see exactly what it changed and go back. Asking the agent to "commit this change" is a good habit. In Activity 2, Claude's self-review shows up as a diff in Source Control.

Git: one history, three copies

Click through seven steps. Each dot is a commit (a save point); yellow ones are yours, blue ones your collaborator's. Every copy of the folder, called a repository, keeps the full history as a tree. 1. You commit A and B on your laptop. 2. Push sends them to GitHub.com (Activity 1, Publish Branch and push). 3. A collaborator clones the repository: their laptop gets the whole history. 4. They commit C. 5. They push C to GitHub. 6. Meanwhile, you commit D, so the history has split into two branches. 7. Pull brings C to your laptop, and Git merges the two branches into M; usually automatic, unless you both changed the same lines. 8. Push again, and GitHub has everyone's work. Nothing is overwritten: every save point is still there, so you can always go back. The same applies when the collaborator is an AI agent: it commits, you review the change, and you can undo it. Today we only use the left half, your laptop and GitHub.com.

Do probiotics prevent diarrhea in children taking antibiotics?

About 4 minutes of agent work

A preview of Activity 2, from my test run on November 18. Claude Code searched PubMed and found 49 trials, screened them and included 17, extracted usable numbers from 11, pooled them in a forest plot (risk ratio 0.58, 95% CI 0.45 to 0.74: about 40% fewer children got diarrhea with probiotics), and wrote a short report with numbered PubMed references. The agent steps took about 3.5 minutes. A literature review like this would take a person days. Your numbers will differ a little from mine and from your neighbor's; that's normal, and a good thing to compare. Note the risk ratio: below 1 means fewer cases with probiotics.

Check it yourself.

From my dry runs. First run: the forest plot page was blank, because the code used a variable named top, which clashes with a built-in browser name. Telling Claude "The page is blank" was enough for it to fix it. Second run: when asked to review its own report, Claude found that it had invented group sizes for one trial and had misordered citations, and fixed them. Self-review helps but can miss things, so Activity 2 ends with you clicking references and checking three studies on PubMed. Finally, compare with the experts: a 2019 Cochrane review of 33 trials found a risk ratio of about 0.45; our quick review gets 0.55 to 0.58. Why might it differ? Abstracts only, one database, a quick search, and a model's judgment in screening. This is a teaching demo, not a real meta-analysis. Plan, produce, review from Session 1 still applies.
